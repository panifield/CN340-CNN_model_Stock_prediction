## a) Feature 4 ตัว

ข้อมูลที่ feature อ่านได้: **แท่ง 10, 11, 12, 14, 15 ของวัน t** (ผ่าน `data1600.day_table` / `known_at_1600` ซึ่งตัดแท่ง ≥ 16 ทิ้งเป็นคำสั่งแรก)
และ **ราคาปิดรายวันของวันที่ < t** (ผ่าน `data1600.daily_before`) · ห้ามอ่านแถว t ของไฟล์รายวันเป็น feature · แท่ง 13 ไม่อ่าน

| ชื่อ | นิยาม | หมายเหตุ |
|---|---|---|
| `r15` | `C15 / Close_official(t−1) − 1` | C15 = Close ของแท่ง 15:00 (Yahoo) |
| `gap` | `O10 / Close_official(t−1) − 1` | นิยามแบบ R2 ของทีม (D2): t−1 = **แถวก่อนหน้าในไฟล์รายวัน** = วันทำการก่อนหน้าจริง ไม่ใช่ eligible day ก่อนหน้า |

## b) Target · Naive · การแปลงกลับ · ตัววัด

```
y(t) = Close_official(t) / C15(t) − 1        predicted_close = C15(t) · (1 + ŷ)        Naive: ŷ = 0 (ราคาปิด = C15)
```

- Close_official(t) = แถว t ของ `task_b_v2/data/<TICKER>_10Y_Cleaned.csv` (ใช้เป็น **target เท่านั้น**)
- ตัววัดเหมือน next_day (LOCK.md หัวข้อ 2): relMAE หน่วย return (หลักที่รายงาน) และหน่วยบาท · MAE/RMSE บาท · IC Pearson + Spearman ·
  DirAcc (ไม่นับวัน y = 0) · StdRatio (ธง) · Diebold–Mariano vs Naive · ใช้ `src.evaluate.metrics(y, ŷ, C15)` ตรง ๆ (prev_close := C15)
- คำทำนายคงที่ → IC := 0 ตามกติกา B39 (`const_ic_zero=True`)
- **c (shrinkage)** ∈ {0, 0.1, …, 1} เลือกจากส่วน early-stop (15% ท้ายของ train) ของแต่ละรอบเทรน · เกณฑ์ลด MAE_return · เสมอเลือก c เล็กกว่า (B18) · รายงานทั้งก่อน/หลังปรับ
- ⚠ AUDIT ข้อ 3: y = 0 พอดี 40–44% ของวัน dev (มากกว่า next_day ที่ 12–22%) → relMAE เอื้อการทาย 0 มากยิ่งกว่า next_day · IC จึงเป็นตัววัดหลักของ "สัญญาณ" (F3) เหมือน B16

## h) Leak test ที่จะเขียน (ก่อนรันโมเดล)

1. **แท่ง 16:00** ของวัน t (ทุก O/H/L/C/V) เปลี่ยนแบบสุ่ม → feature ของแถว t และคำทำนายต้องไม่เปลี่ยน (มีแล้วระดับ `data1600` · จะเพิ่มระดับ feature + คำทำนาย)
2. **แถว t ของไฟล์รายวัน** (และทุกแถวหลัง t) เปลี่ยน → feature 4 ตัวและภาพของแถว t ต้องไม่เปลี่ยน (target เปลี่ยนได้)
3. **ข้อมูลทุกอย่างหลัง 15:00 ของวัน t** (แท่ง ≥ 16 ของวัน t + แท่งทุกแท่งของวัน > t + รายวัน ≥ t) เปลี่ยน → feature และคำทำนายของแถว t ต้องไม่เปลี่ยน
4. **replay**: feature ที่สร้างจาก snapshot ต้องเท่ากับที่สร้างจากไฟล์ล็อก 730d บนวันที่ข้อมูลตรงกัน
   (วันที่ทับกันใน snapshot 2026-10-23 03:55 = 2026-07-24 → 2026-09-25 · AUDIT ข้อ 5 ค: แท่งตรงกัน 100% → feature ต้องตรงทุกตัว)
5. walk-forward: ทุกแถว train ของรอบ < วันแรกของบล็อก · สถิติ scaler/สเกลภาพ/normalize มาจากแถว fit เท่านั้น (assert ในโค้ด)
6. `vol15` ของวัน t ใช้ปริมาณของวันก่อนหน้าเท่านั้นในตัวหาร (เปลี่ยน V ของวัน t → ตัวหารไม่เปลี่ยน)
